- 节点插入、编辑、移动、拆分、合并、删除；选区问题、追问、阅读位置及返回主线。

- 从讨论“整理成正文节点”或直接“用 AI 写节点”；流式预览、取消、候选正文与引用依据校验；采用时正文与 AI 解释关联一起提交，支持整组撤销。

## 状态的含义

聊天回答、写作安排、候选正文和已采用正文分别保存。只有正文中的解释关联参与当前阅读路线的覆盖计算；聊天回答或“安排在下一节解释”不会提前把问题标为已解释。

AI 解释关联是模型提出的正文覆盖判断，必须带有可定位的引用，并通过问题、节点和版本检查。结构有效不保证语义上回答充分。用户可以查看依据、移除关联或修正正文；“已解释”始终不表示读者已经理解。

## 验证边界

直接模型后端使用协议夹具验证，未使用真实账户发起付费调用。Cowork 的数据协议经过测试，尚未在真实客户端完成来回交接。浏览器验证使用真实 UI、核心、控制器和内存文件系统；并未替代 Obsidian 原生 Markdown / 公式渲染、文件事件和操作系统输入法验证。Codex 与 Claude Agent SDK 尚未接入。

存储采用单活动写入者。`.md` 与 `.explainweave.json` 使用意图记录恢复未完成的正文提交；`.explainweave.sessions.json`、草稿和交接文件独立保存并检测已知外部冲突，没有跨全部文件的原子事务。文件系统也不提供跨应用原子 compare-and-swap，因此不能宣称支持多个编辑器或设备同时写入。正文提交后若旁文件保存失败，需要单独处理，不能把失败当作正文尚未采用并重复插入。

撤销记录保留在打开的笔记会话中，重启或外部更新后不能继续撤销旧操作。正文、问题、阅读位置、已保存聊天和草稿可以恢复。恢复时将中断的生成标为已取消，并保留已保存片段；进程突然退出仍可能丢失尚未落盘的流式内容。文件重命名时尝试迁移伴随文件，复杂同步冲突须保留原文件处理。

同一讨论追加原始消息与文档增量，保持此前已发送的消息前缀；目前不自动 checkpoint、不静默删减历史。完整历史与增量会持续增长，受本地文件 / 字段大小及服务上下文长度限制；超限报错并保留数据，不能保证长会话无限继续。底层保留 checkpoint 能力，显式重建、总结压缩和新会话管理仍待实现。没有实测缓存命中率或成本收益，也不保证服务端会复用缓存。
