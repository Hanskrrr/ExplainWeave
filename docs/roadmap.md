# 开发计划与验收

当前为 0.2 开发预览：已实现 M0–M1 主要流程、M2 文章 / 问题讨论与候选正文闭环，以及 M3 的直接模型适配和 Cowork 交接协议。追加上下文也已接入请求。原生应用、真实服务和缓存收益尚未验收，因此不把这些里程碑整体标为完成。当前状态见 [实现状态](status.md)，测试结果见 CI / 本地验证。

## M0 — 工程骨架与存储验证

建立 TypeScript workspace、Obsidian 桌面插件入口、可独立测试的核心和确定性模拟 AI 后端。用独立测试 Vault 开发。

使用公式、代码块、嵌套列表、frontmatter、重复段落和外部编辑样例，验证稳定节点标记、伴随元数据、拆分合并、文件重命名和写入中断后的恢复。正文与解释元数据使用可恢复的两文件提交；讨论、安排和日志写入 `.explainweave.sessions.json`，草稿另存，分别验证损坏保护和外部冲突拒写，不假设跨所有文件原子提交。

**验收：** 不改动原文的导入导出逐字一致；受管理编辑只改目标范围；缺失或重复锚点有明确恢复路径；插件禁用后正文仍可阅读。损坏或超限的旁文件不能被空状态覆盖，正文已提交而旁文件保存失败时不能重复插入。

## M1 — 可实际阅读和编辑的离线版本

提供 Notebook 节点视图、连续阅读、节点操作、选区问题、聚焦问答支线、返回主线、解释关联及撤销恢复。离线模拟支持文章讨论、父支线继承、后续安排和候选正文，无需 API 凭据即可验证交互。

**验收：** 在三节文章中提出问题，安排第三节解释，再采用带引用的补充节点；移动或删除解释后，当前位置状态、正文和关系一致。安排和聊天回答不算已解释；把“为什么下降”改为“为什么一定收敛”时，旧解释进入待检查。重启后问题、已保存讨论、安排、草稿和阅读位置保留，中断的生成保留片段并显示已取消。中文输入法、键盘操作、窄窗和长文章的焦点与滚动仍需原生应用验收。

## M2 — 第一个真实 AI 闭环

DeepSeek / Claude API 已实现流式生成、取消、结构校验及采用前版本检查。当前入口包括 **讨论这篇文章**、问题内 **发送**、**安排在后续节点解释**、**整理成正文节点** 和 **用 AI 写节点**。用户在候选区检查正文及解释引用，再点击 **采用为后续解释**；正文与该草稿的解释关联一起提交，顶部 **撤销** 一起撤回。

完整讨论历史和父支线背景参与请求，不静默截断。同一讨论保留模型原始消息前缀，后续节点更新、删除记录、顺序及新问题追加到末尾；结构化生成的原始 JSON 与界面显示的 Markdown 分开保存。

**验收：** 用真实后端完成“文章讨论 → 就地追问 → 安排后文 → 整理候选正文 → 采用 → 整组撤销”。在生成期间编辑正文、删除目标、取消和重试，均不覆盖新内容或重复采用。模型声称覆盖某问题时，必须给出候选正文中唯一可定位的引用，且采用前问题和正文版本有效；该检查不代替用户对语义充分性的判断。没有真实凭据的验证只标为模拟或协议通过。

## M3 — 多后端与现有 Agent 互通

直接模型适配与 Cowork 任务交接已存在；Codex 本地会话与 Claude Agent SDK 尚未接入。接入 Codex 时，对安装版本生成 / 校验协议；确有工具循环需求时再加入 Agent SDK。

**交给 Cowork** 导出任务和必要上下文，通过官方深链接打开客户端；用户在客户端发送，回收 `return.json` 后预览并采用。首版允许手动选择返回文件；自动回流和 MCP 另行验证。

**验收：** 至少两个真实后端通过同一套用户场景，切换后端不丢文章状态。Codex 的开始、继续、取消和退出可验证；Cowork 使用实际客户端验证“已打开”“已提交”“已回收”，打开链接不能当作任务完成。

## M4 — 连贯性、上下文预算与可日用测试版

增加影响范围提示、补写后的衔接复查、显式新会话 / 上下文重建、可审查的总结压缩、请求成本比较和安装发布流程。底层已有 checkpoint API，但当前请求不自动使用：只重置文档日志不会缩短已保留的原始讨论消息，因此真正重建必须明确处理整条会话及可恢复历史。

当前完整历史和增量可能持续增长，本地保存和服务上下文均有上限；超限须报错并保留数据，不静默删除旧记录。后续为这些边界提供可见预算与恢复入口，再比较保留前缀和显式重建的总成本。

**验收：** 删除、重排、重复文本、不同步的伴随文件、API 中断、过期草稿与应用重启均有可验证的恢复路径；数据升级、卸载重装和备份恢复通过回归。缓存读取、输出、延迟与总任务开销有可重复的真实服务测量，不能以理论前缀稳定代替收益证明。完成原生环境与真实服务验证后再推进日用测试发布。

## 首版后再做

- 多阅读路线和跨文章解释依赖。
- 更完整的图谱可视化及重排辅助。
- 经实测的 Cowork MCP 回流。
- 独立桌面或 Web 前端，复用已有文档核心。
- 持久撤销、多设备并发协作和更广泛的聊天记录导入。

## 验证方式

核心测试集中在覆盖语义、版本冲突、编辑不变量和恢复；适配器用协议夹具测错误路径，再做实际服务验证。UI 测真实交互、选区、输入法、滚动位置与取消，不以截图或“能编译”代替验收。离线流程可独立运行；真实服务和客户端验证需要相应已配置的账号与环境。
