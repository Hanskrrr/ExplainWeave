# 开发计划与验收

当前已有覆盖 M0–M1 主要流程、M2 直接模型适配和 M3 Cowork 交接的开发预览。应用内与真实服务验收尚未完成，因此不把这些里程碑整体标为完成。具体已实现项与限制见 [实现状态](status.md)。

## M0 — 工程骨架与存储验证

建立 TypeScript workspace、Obsidian 桌面插件入口、可独立测试的核心和确定性模拟 AI 后端。用独立测试 Vault 开发。

先完成少量但真实的 Markdown 样例：公式、代码块、嵌套列表、frontmatter、重复段落和外部编辑。验证稳定节点标记、伴随元数据、拆分合并、文件重命名和一次写入中断后的恢复。通过后冻结第一版存储格式及迁移入口。

**验收：** 不改动原文的导入导出逐字一致；受管理编辑只改目标范围；缺失或重复锚点有明确恢复路径；插件禁用后正文仍可阅读。

## M1 — 可实际阅读和编辑的离线版本

提供 Notebook 节点视图、连续阅读、节点插入/移动/拆分/合并、选区问题、聚焦问答支线、回到主线、解释关联及撤销恢复。此阶段无需 API 凭据，也能验证完整交互。

**验收：** 在三节文章中提出问题、让第三节关联解释、插入补充节点，再移动或删除解释；当前位置状态、正文和关系一致。已解释状态随问题版本、回答版本与路线变化；将“为什么下降”改成“为什么一定收敛”时，旧解释须进入待检查。重启后问题、草稿和阅读位置保留。中文输入法、键盘操作、窄窗和长文章不能丢焦点或跳回文首。

## M2 — 第一个真实 AI 闭环

先接 DeepSeek 直接模型 API，完成就地回答、问题集合、缺失衔接建议和补写草稿。实现流式输出、取消、错误恢复、结果结构校验、采用前版本检查和基础用量记录。上下文从第一版开始分离文档排列与任务消息排列。

**验收：** 用真实后端完成“提问 → 回答 → 插入解释 → 关联先前问题”。在生成期间编辑、删除目标、取消和重试，均不覆盖新内容或重复采用。模型声称覆盖某问题时，必须指向有效正文范围。没有真实凭据的验证只标为模拟通过。

## M3 — 多后端与现有 Agent 互通

沿用同一文档任务格式接入 Claude API；实现 Codex 的本地会话适配器，并对安装版本生成/校验协议。需要 Claude 的 Agent 工具循环时，再加入 Claude Agent SDK 适配器。

同时实现“交给 Cowork”：导出当前任务及必要上下文，通过官方深链接打开客户端，回收文件后预览并采用。首个交接版本允许用户选择返回文件；自动回流和 MCP 另行验证。

**验收：** 至少两个真实后端通过同一套用户场景；切换后端不丢文章状态；Codex 的开始、继续、取消和退出可验证；Cowork 交接使用实际客户端验证，明确区分“已打开”“已提交”“已回收”，打开链接不能当作任务完成。

## M4 — 连贯性检查与可日用测试版

增加影响范围提示、补写后的衔接复查、长文上下文检查点、请求成本比较、外部编辑冲突恢复和安装发布流程。对数据格式升级、插件卸载重装和备份恢复做回归验证。

**验收：** 删除、重排、重复文本、不同步的伴随文件、API 中断、过期草稿与应用重启均能恢复；连续增量写作与重建上下文的实际开销有可重复的测量。通过后才提供真实 Vault 的安装包。

## 首版后再做

- 多阅读路线和跨文章解释依赖。
- 更完整的图谱可视化及重排辅助。
- 经实测的 Cowork MCP 回流。
- 独立桌面或 Web 前端，复用已有文档核心。
- 多设备并发协作和更广泛的聊天记录导入。

## 验证方式

核心测试集中在覆盖语义、版本冲突、编辑不变量和恢复；适配器用协议夹具测错误路径，再做实际服务验证。UI 测真实交互、选区、输入法、滚动位置与取消，不以截图或“能编译”代替功能验收。M0–M1 可完全离线完成；真实服务和客户端验证需要相应已配置的账号与环境。
